# MasLingo v1.1.8

日漫全平台 OCR 翻译器浏览器插件。根据 OCR 原理，可以自动检测当前可见页面中的文字区域翻译当前页面，或者框选翻译；翻译开启后，扩展在原图文字范围内修复背景并绘制中文。

由于原理决定，插件并不会像其它插件一样需要平台支持。

**⚠️服务器未上线**：识别由官方托管的 MangaOCR 后端完成，原则上普通用户不需要安装 Python、不需要下载模型，装完扩展就能用。但是由于服务器未上线，只能自行部署于本地。

## 安装与运行

### 本机部署

```
Edge / Chrome 扩展（加载 extension 文件夹）
        │  http://127.0.0.1:8001
        ▼
你电脑上的 FastAPI + MangaOCR（start-backend.ps1）
```


### 1. 安装 Python 3.11.x / 3.12.x

访问 <https://www.python.org/downloads/> 下载安装，**安装时勾选 “Add python.exe to PATH”**。装完打开 PowerShell 确认：

```powershell
python --version
```

显示 3.11.x 或 3.12.x 即可。

### 2. 下载本项目

```powershell
git clone https://github.com/YaekaCutie/MasLingo.git
```

若未安装 Git，在 GitHub 页面点 **Code → Download ZIP**，解压到本地目录。

### 3. 创建环境并安装依赖

在项目目录里执行：

```powershell
cd MasLingo
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r backend\requirements.txt
```

- 如果提示“禁止运行脚本”：先执行 `Set-ExecutionPolicy -Scope Process Bypass`，再运行激活命令。
- 国内网络下载慢，可以在 pip 命令末尾加 `-i https://pypi.tuna.tsinghua.edu.cn/simple`。

### 4. 启动后端

```powershell
.\start-backend.ps1
```

- **首次启动会联网下载 OCR 模型**（数百 MB，缓存在 `C:\Users\<你>\.cache\huggingface`），需要一两分钟；日志出现 `OCR ready` 就是就绪。
- **这个窗口保持开着**，关掉窗口就等于后端停止；`Ctrl-C` 可以停止。

### 5. 验证后端

浏览器打开 <http://127.0.0.1:8001/health>，看到

```json
{"ok":true,"backend":"ready","ocr":"mangaocr","busy":0,"concurrency":2,"free_translate":true}
```

即成功。

### 6. 加载扩展

Edge 地址栏输入 `edge://extensions`（Chrome 为 `chrome://extensions`）→ 打开「开发人员模式」→「加载解压缩的扩展」→ 选择项目里的 `extension` 文件夹。装好后工具栏出现 MasLingo 图标。

### 7. 指向本机后端

`http://127.0.0.1:8001` 与 `http://localhost:8001` 是扩展内置的默认回退地址，**通常什么都不用设置**。只有换过后端端口（见常见问题）时，才需要到扩展「识别设置」里手动填写后端地址。

### 8. 使用

打开任意漫画页 → 点 MasLingo 图标 → 框选翻译某个区域，或点「自动识别」整页。翻译默认关闭（先只出日文原文）；要开启翻译模式，在「识别设置」里选择翻译来源并保存。

### 9. 更新方式

- **后端**：`git pull` 后重启——`Ctrl-C` 停掉，再运行 `.\start-backend.ps1`。
- **扩展**：到 `edge://extensions` 点 MasLingo 下的「重新加载」，然后刷新漫画页。

### 10. 可选：开机自启

按 `Win+R` 输入 `shell:startup` 回车，把 `start-backend.ps1` 的**快捷方式**放进打开的文件夹。以后登录 Windows 会自动启动后端（会弹出一个 PowerShell 窗口，属正常）。

### 本机部署常见问题

- **端口 8001 被占用**：多半是已经有一个后端在跑（任务管理器里找 `python` 进程）。换端口启动：`python -m uvicorn backend.app:app --host 127.0.0.1 --port 8002`，然后到扩展「识别设置」把后端地址填成 `http://127.0.0.1:8002`。
- **识别一直失败**：先确认第 5 步的 `/health` 能打开；再确认扩展设置里的后端地址为空或者与本机地址一致。
- **首次识别很慢**：模型还在加载或下载，属正常；之后会快很多。
- **模型下载中断**：重新运行 `.\start-backend.ps1` 会续传，已下载的部分保留在 `~/.cache/huggingface`。
- **数据去哪了**：本机部署模式下，截图只经 `127.0.0.1`，不离开这台电脑；只有你主动开启翻译后，识别出的文字才会发给所选翻译服务。

## 数据流与限制

`可见页面/手选区域截图 → 后端（默认为官方托管实例，可改为本机） → 文字区域分组 + MangaOCR 日文识别 → 扩展显示结果`

自动模式优先识别视口内最大的主要图片/画布/视频或带背景图的元素，先裁掉网页搜索栏、工具栏和缩略图，再用本地对比度与邻近墨迹分组检测文字，可检测深色或浅色的嵌图文字；亮字候选还需有足够暗色邻域，避免把白色气泡底纹当作文字。对紧凑形状、浅色连通区域且包含足够墨迹的对白气泡，会额外生成整气泡 OCR 框，避免多列文本被分段裁切；该类框最大为图像面积的 16%，普通墨迹分组框仍限制为 5%。候选按“字形似度”排序（画稿不容易挤掉文字），画格的整块背景框不会吞并格内气泡，描边相连的相邻气泡会按无字空白带拆分。深色背景上较大的亮字分组会有限扩展纵向上下文，帮助保留结尾字词。高窄竖排区域会优先保留横向上下文供 OCR 识别。找不到足够大的主媒体图片时，自动模式会明确报错并提示手动框选，不会退回扫描整个网页。检测仍是启发式，不推断精确气泡轮廓，复杂背景、网点或相邻对白可能漏检/合并，仍可手动框选。后端会比较两种明暗极性判断横排/竖排，并按日漫竖排从右至左识别文字列；识别结果要过一道置信度门槛：低于阈值或明显是画稿纹理的读数会被丢弃，不会被翻译后画到画面上。每次识别前会移除旧结果，避免旧结果进入新截图。翻译开启后，扩展在浏览器中从周边画面采样并估算文字区域底色，用原图裁片修复原字位置，再按横排或竖排绘制中文；不会添加窗口、卡片、边框或气泡底板。背景复杂或文字紧贴画框时，局部修复可能不完美。关闭翻译、请求失败或超时时会保留原始画面并显示状态提示。

翻译默认关闭，因此默认流程不会联系云端翻译服务。启用后，翻译方向为日文到简体中文：Google 翻译请求固定使用 `ja → zh-CN` 并整条提交 OCR 文本；OpenAI-compatible Chat Completions API 使用日漫本地化提示，结合当批条目的上下文翻译，并要求保留原意、编号及条目数量。可在扩展设置选择 OpenAI-compatible API 并填写 endpoint、模型以及可选 API Key，也可显式启用 Google 翻译。OpenAI-compatible 设置（包括 Key）仅存于 Chrome `storage.local`；Key 随本次翻译请求从扩展发往后端，再转发到所配置的接口，不写入后端配置或日志。选择在线服务会将识别文本发送给该服务。也可配置本地运行的 OpenAI-compatible 服务以避免云端。

选择「AI 大模型」来源时，面板上有三档翻译强度：**Low（不联网轻度润色）/ High（联网润色）/ Max（联网完美翻译）**。三档都要求人名、地名、技能名等专有名词在整批译文中前后一致，档位越高越强调联网核对官方译名与逐条自查。旁边的「增强识别」开关会把整页截图直接交给支持视觉的模型：由模型自己找出文字位置并给出译文，识别与翻译合成一次请求（适合排版复杂、气泡分割困难的页面；模型需要支持看图，失败时会报出具体原因）。

## 隐私与数据

这是使用前必须知道的部分：

- **默认情况下，你框选或自动检测到的页面画面会离开你的设备**，发送到官方托管的 OCR 后端做文字识别。这是“装完即用”的代价——识别模型必须跑在某台机器上。
- 托管后端**只做 OCR**：不写入请求体日志、不做训练、不做广告用途、不长期保存截图。进程只保存模型，不保存用户图像。
- 想让数据完全不出本机：按上面「本机部署」把后端跑在自己电脑上；截图只经 `127.0.0.1`，不离开这台电脑。
- **翻译是另一个独立选择**，默认关闭。启用 Google 翻译会把识别文本发给 Google；启用 OpenAI-compatible 会把文本发给你自己配置的接口。不启用就只做 OCR。
- 相关信息：扩展只在你点击扩展图标后才对当前标签页截图，不会后台持续采集。

## 常见问题

- **识别很慢或失败**：使用托管后端时，第一次请求要等模型加载（托管实例已开启预加载，通常不会遇到）。本机部署时首次运行需初始化 MangaOCR 模型，确认安装依赖时网络可用，并为模型文件和运行时预留足够磁盘及内存。
- **自动识别要等几十秒**：整页模式要检测并逐个识别最多 80 个区域（普通单页几秒到十几秒，密集双页可能二十多秒到一分钟），在低配服务器上是正常耗时；手动框选单个区域通常 1–3 秒。嫌慢就用框选。
- **自动识别结果为空或区域不准**：自动检测是轻量图像启发式，适用于清晰墨迹文字，不保证气泡分割质量；尝试调整页面缩放或手动框选单个文字区域。
- **从源码加载的扩展识别一直失败**：仓库里的 `extension/` 没有内置托管后端地址，会回退到本机 `127.0.0.1:8001`——按「本机部署」先把后端跑起来即可；发布用的 `.crx` 不受影响。
- **结果只有日文、没有中文**：翻译默认关闭以避免未经允许发送漫画文本。打开扩展的“识别设置”，将“翻译模式”从“关闭翻译”改为“Google 翻译”或配置好的“OpenAI-compatible API”，然后保存；Google 翻译需要联网。翻译未启用或服务报错时，页面会提示原因并保留日文原文。
- **翻译报“无法连接「XX」（域名）：Failed to fetch”**：说明这个翻译服务从你的网络**无法直连**，与扩展本身无关。国内网络访问 Google 翻译、OpenAI、Anthropic 等通常需要代理；Google 翻译是最顺手的免密钥来源，也最容易连不上。到“识别设置”里把翻译来源换成「必应翻译」或「MyMemory」（免密钥、国内可直连），或 DeepSeek、通义千问、智谱等（需要各自的 API Key），或本机运行 Ollama。
- **提示“请求过于频繁”**：托管后端对每个 IP 做了限流，稍等几十秒再试即可。

# MasLingo 接手后的改动、原因与结果

本次工作的代码基线是 `b66bb68ddec27653646383b2f6948d4c3e8986b3`，提交时的工作分支为 `review/2026-11-01`。报告覆盖源码本地部署、自动漫画识别与擦字、真实样本验证，以及后续按反馈完善的竖排和旁注交互。

仓库原本已经有 MangaOCR、自动识别、框选翻译、DeepSeek 等翻译来源、网页悬停和划词翻译。本次是在这些功能上修复和扩展，没有把已有功能当作新增成果。特别是：DeepSeek 适配器原本就存在，本次用用户授权的 Key 做了真实连接验证，并修复了影响漫画翻译的语言判断；没有从零新增一个 DeepSeek 供应商，也没有删除必应适配器。

任务最初包含全仓审查，之后按用户要求优先处理 Windows 源码部署和自动日漫翻译，最后降低了审查篇幅。因此，已有文件清单、语法检查和重点模块审查，不等于整个仓库已经完成逐文件人工审查。

工作推进的主要阶段如下。

| 阶段 | 当时的要求或证据 | 做出的决定 |
| --- | --- | --- |
| 本地运行 | 发行版不完整，目标是 Windows Chrome/Edge | 先完善源码环境准备和后端启动，不把重做安装器当作本次前提 |
| 检测与擦字 | 彩色、无气泡文字漏检，框不准，擦字伤背景或漏擦 | 引入 RGB 漫画文字检测和笔画分割，把检测框、擦字掩膜和译文绘制分开处理 |
| 复杂背景 | 用户明确选择“修补不可靠时保留原文，在附近显示译文” | 对不可靠区域采用保留原图与旁注，避免强行重建线稿 |
| 实图迭代 | 收到三张漫画的 ZIP 后，复现合框、小字丢失和旁注遮挡 | 调整行列分组、OCR 边距、受限重读和旁注避让 |
| 排版与交互 | 普通气泡误用旁注，多行要优先竖排，“一”和破折号难分 | 单独确认气泡内部底色，增加竖排偏好、破折号旋转、旁注拖动和来源标记 |

原来的自动路径主要是：图片整体缩小、启发式找墨迹、MangaOCR 读取，再由浏览器根据区域像素或回退底色覆盖。当前默认路径变为：原图按宽度保留分辨率并分段、ONNX 模型输出文字行列与笔画概率图、MangaOCR 读取、后端生成可信的透明修复层、翻译服务返回译文、浏览器分别绘制修复层和文字。不适合修补的区域保留原文并显示旁注。

没有训练新检测模型，也没有更换 MangaOCR 权重。新增的是上游预训练检测权重的加载、校验、坐标映射、分组及掩膜集成；MangaOCR 仍负责读字。这也是为什么检测范围和漏框改善后，低分辨率相似字仍可能读错。

| 原来的现象 | 原因 | 具体改动 | 结果与影响 |
| --- | --- | --- | --- |
| 彩色文字、同亮度异色文字和无气泡旁白漏检 | 旧检测主要依赖灰度墨迹特征，画稿与文字不易分离 | 新增 `backend/ocr/text_detector.py`，默认以 RGB 输入固定的 comic-text-detector ONNX 模型，保留旧 heuristic 对照入口 | 不再以白色气泡作为识别前提；增加约 95 MB 的首次模型下载和 ONNX/OpenCV 依赖 |
| 长条漫画的小字被缩没 | 原流程按整张图片最长边缩放，长图高度决定缩放比例 | `extension/content/auto.js` 保留宽度，按最多 1600px 高的重叠段识别并去重 | 长图小字能保留更多源像素；长图需要多次 OCR 请求，运行时间随长度增加 |
| 两个气泡合成一框，整块对白串读 | 粗文字块包含多个气泡或段落；行框先扩张会抹掉列间距证据 | 先按未扩张的文字行/列间距分组，再依据笔画概率恢复边缘 | 相邻气泡、相距较远的段落能够拆开；分组仍是启发式，不能保证所有页面都正确 |
| 单字「え」等已被模型检出，却没有译文 | 过大的 OCR 边距带入气泡边线，使读取结果未通过置信度检查 | 收紧到有笔画证据的范围，并保留较小边距 | 实图中找回「え」「し」等文字，减少边框干扰 |
| 收紧边距后，原本可读的「わたし帰る…」被过滤 | OCR 对裁切边界和省略号较敏感，单次裁切的置信度不稳定 | 对神经检测框中未通过检查的日文，最多增加 2px 上下文重读一次，仍使用原有置信度门槛 | 找回该句；只扩大 OCR 上下文，不扩大擦字区域，也不无限重读 |
| 自动擦字有整块白色覆盖或明显底色痕迹 | 自动路径未把真实原图像素传给共享渲染器，可能退回底色覆盖；矩形也不等于文字笔画 | 传递实际原图像素；新增 `backend/image/erase.py` 输出笔画位置的透明 PNG 修复层 | 默认自动模式不再依赖整块白色覆盖；掩膜外仍由原图提供像素 |
| 字边残留，或擦掉旁边画框 | 模型边缘有低置信度与抗锯齿/JPEG 痕迹；单纯扩大矩形会伤及邻近线条 | 弱边缘仅在连接到强笔画种子时纳入，使用小范围扩张，并对接近底色的压缩边缘补全 | 减少残边，同时约束修补范围；仍不能保证所有压缩图无漏擦或误擦 |
| 复杂纹理上修补过多，破坏头发、排线或网点 | 局部 inpaint 必须猜测被文字遮住的背景，掩膜准确也不代表能恢复原画 | 根据笔画周围纹理和掩膜覆盖率判断风险，不可靠时不返回修复图片，前端保留原文并显示旁注 | 按用户偏好优先保留画面；代价是复杂嵌字区域不会全部自动消除原文 |
| 普通气泡也被当成复杂嵌字，出现不必要的旁注 | 纹理采样读到了气泡边线，裁切外的画面也可能影响底色估计 | 优先参考笔画附近底色，寻找封闭、平滑的气泡内部区域；排除文字后确认底色，并将修补约束在气泡内部 | 三张实图中的四个误判气泡恢复正常擦字，紫底嵌字继续保留；纹理气泡仍可能保守回退 |
| 页面缩放后修复层与原文字错位 | 单独取整 CSS 坐标导致像素边缘不重合，图片显示区域也可能有留白 | 保留小数 CSS 坐标，以图片实际内容区域定位结果 | 常规图片缩放和居中 contain 场景更准确；复杂 object-position/cover 仍未完全覆盖 |
| 已翻译图片换页后不处理，或旧结果落到新图 | 只看节点新增，没充分跟踪 src/srcset/style/load；异步结果缺少媒体和任务代次约束 | 观察来源变化，清理对应图层和记录，丢弃过期请求；返回之前的图片也能重画 | 同一元素换页可以重新识别，减少旧页覆盖新页 |
| 关闭自动翻译后仍发送后续请求或绘制 | 正在执行、等待重试和读取启动设置的流程，可能在关闭后继续 | 代次检查覆盖待启动、设置读取、OCR 后翻译、迟到绘制；取消旧设置读取 | 新增延迟启动、设置逆序返回的检查，关闭后不会被旧启动流程重新开启 |
| 失败图片反复重试 | 用完重试次数后重新观察同一媒体，会重置尝试次数 | 记住失败媒体，限制每轮图片失败尝试次数 | OCR/取图失败不会无限占用队列；翻译设置变化后的已有结果刷新仍待完善 |
| 「用事」「若様」保持日文，不发送翻译 | 通用同语言跳过逻辑把只有汉字的日文当成中文 | 漫画 OCR 与明确选择的源语言按已知源语言处理；网页自动语言识别保留原有跳过逻辑 | 纯汉字日文进入翻译，例如真实测试中的「若様」译为「少主」 |
| 多行译文横排、字号过小 | 方向不明时依赖区域长宽比；排版先估计行列，再缩字，重新分行后没有恢复合适字号 | 自动漫画需要换行时优先竖排，联合选择字号与行列数，从右向左分列 | 多行更接近日漫阅读顺序；短句不会无必要地缩小，长句仍受区域大小约束 |
| 竖排“一”和破折号看起来一样 | Canvas 逐字绘制时，破折号仍保持横向字形 | 竖排时旋转破折号等长横线符号，汉字「一」不旋转 | 两者的方向可区分；这是显示修复，没有把 OCR 的「一」强行替换成标点 |
| 旁注遮挡已翻译文字，不知道对应哪句原文 | 原位置选择只充分避让自身文字；后画的 canvas 还会覆盖卡片 | 优先利用图片两侧空白，避让其他文字层，提高控件层级；增加同编号原文标记、高亮、定位和连接线 | 旁注更易追踪；用户主动移动后仍可临时覆盖部分画面，但原图像素不变 |
| 旁注不能移动 | 原卡片仅自动定位 | 顶部支持指针拖动，方向键微调，双击或 Home 归位；位置随图片滚动和缩放，换图清理卡片与关联标记 | 用户可自行放置复杂嵌字译文；拖动事件不会触发阅读器的翻页处理 |

其他配套修改也解决了运行和诊断问题。

| 修改 | 为什么需要 | 影响 |
| --- | --- | --- |
| 新增 `setup-local.ps1`，完善 `start-backend.ps1` | 源码运行需要创建环境、安装 CPU 依赖并准备两个模型；从其他工作目录启动也应可靠 | 支持 Python 3.11/3.12 的环境准备、明确的失败信息、端口参数；Windows 启动默认 2 个计算线程与 1 个 OCR 并发 |
| 后端启动时预加载检测器和识别器，失败则终止启动 | 原来预加载失败仍可能启动成功，随后请求才暴露问题 | 模型不可用时不会把失败隐藏到第一次识别；默认启动必须先准备好模型 |
| 截图前后检查活动标签页，拒绝 iframe 坐标回退 | 标签切换可能截到其他页面；iframe 局部坐标不能直接裁顶层截图 | 减少错误标签截图与坐标误用；无法读取 iframe 图片时可能需要顶层框选 |
| Google 后端拼接所有翻译段，异常格式按失败处理 | 原来只取首段，部分长句被截断，异常时还可能回原文当成功 | 修正保留的旧适配路径；后续实际漫画翻译验证使用 DeepSeek |
| 移除后端日志中的识别原文 | 调试进度不需要记录漫画对白内容 | 仍保留区域、进度、置信度，减少后端日志中的内容暴露；不等于所有前端日志都经过同样清理 |
| 托管配置脚本保留既有扩展权限 | 原脚本可能覆盖翻译来源需要的 host permissions | 配置 OCR 地址后不会删除已有翻译域名权限 |
| 更新 Dockerfile、运行时依赖和未来打包脚本 | 新检测模型和依赖必须能进入相应运行环境 | 增加 ONNX/OpenCV 与检测模型准备；本次未构建安装包或发布 Release |
| 新增第三方说明与 GPL 文本，固定模型 SHA-256 | 需要明确权重来源、下载完整性和附带许可 | 模型校验失败时明确报错；权重不进入 Git，后续分发权重需保留相应说明 |
| 增加回归检查与评估工具，接入 CI 配置 | 需要把实际遇到的故障变成可重复的检查 | 覆盖取图来源、纯汉字日文、图片生命周期、擦字、竖排和旁注交互；CI 配置存在不代表远端已运行通过 |

主要新增工具为 `tools/evaluate_text_pipeline.py`、`tools/evaluate_repair_policy.py` 和 `tools/evaluate_manga_pages.py`，分别用于可控样本对照、背景修补风险隔离、真实本地图片的 HTTP OCR 结果保存。

三张 ZIP 实图的结果经历了分组修复和气泡修复两个阶段。下表起点是这些实图刚接入测试时、已经加入 ONNX 检测器的中间版本，**不是原始提交在同一三图上的完整基线**。

| 实图 | 尺寸 | 接入实测时接受的文字组 | 当前文字组 | 中间版本的旁注数 | 当前旁注数 |
| --- | --- | ---: | ---: | ---: | ---: |
| 彩色六格 | 474×681 | 10 | 14 | 3 | 1 |
| 黑白双页 | 1493×1080 | 18 | 21 | 2 | 0 |
| 黑白校园 | 700×1024 | 6 | 9 | 0 | 0 |

组数增加既包含找回漏读，也包含把粗框拆成合理段落，不能当成识别准确率。校园图核对了九组文字，包括「用事」「え？」「え」「し」「どうしたの？」「思い出した」「え？ちょっ…」「用事を思い出したからっ」「わたし帰る…」。

彩漫当前保留的旁注来自紫底无气泡旁白。对其原图区域 `(222,543)–(263,623)`，擦字合成结果与原图 RGB 数组完全一致。其余四个误判的普通气泡已恢复局部擦字。旧的 813×2163 彩色长图也保留了五处主要对白；页脚中文水印仍会被日文 OCR 误读，没有计作成功解决。

| 合成样本 | 旧 heuristic 文字像素覆盖 | 当前检测框覆盖 |
| --- | ---: | ---: |
| 白色气泡 | 50.89% | 99.89% |
| 彩色气泡 | 50.89% | 99.77% |
| 近似亮度的异色文字与背景 | 0% | 100% |
| 渐变底无气泡对白 | 9.61% | 100% |
| 深底亮字 | 100% | 100% |
| 彩色竖排 | 27.28% | 100% |

这六种样本在 OCR 验证阶段全部读出目标句。最后一次仅针对擦字逻辑的回归没有重新跑 OCR；在字形外扩 2px 之外，没有测得通道差值大于 3 的背景变化。真实漫画没有文字遮挡前的干净底图，因此不能用这个结果宣称真实背景恢复完全正确。

另外，使用已知干净底图与精确字形掩膜做过修补风险试验：强行局部修补后，原文字遮挡处的平均 RGB 绝对误差为纯色 0.000、紫色排线 15.989、网点 40.965、线稿 77.637，通道范围为 0–255。这说明即使字形掩膜准确，也不能稳定重建复杂纹理，是保留画面策略的实际依据。

验证结果和边界如下。

- 后端单元测试从早期的 82 项逐步增加到当前 **91 项，全部通过**。新检查包括 RGB/坐标映射、分组与小字边距、受限重读、修复掩膜、气泡边线保护和纹理回退。
- 浏览器回归检查通过，包含图片换页、长图分段、停止、有限重试、取消待启动、旧设置返回、旁注避让、层级、真实鼠标拖动、编号关系、原文定位、滚动、窄窗口、换图清理、多行竖排与破折号/一的实际像素形状。
- 扩展结构检查与 21 个翻译来源的适配器检查通过。适配器检查主要验证请求构造和响应解析，不能代表 21 家服务都经过真实账号调用。
- 已做过 Python、JavaScript 和 shell 的静态语法检查；它们不能替代运行测试或逐文件人工审查。
- DeepSeek 真实请求成功，使用账号可用的 `deepseek-flash`；三张新图分别提交真实 OCR 文本，返回条目数为 14、21、9。后续排版与擦字迭代重放这些真实结果，没有重复调用翻译 API。
- Key 未写入源码、模型配置、报告或提交；测试用不回显输入送入进程内存。用户原图、模型缓存、虚拟环境和本地截图也没有纳入本次 Git 提交。
- 运行环境是 Linux + Chromium。当前环境的管理员策略禁止加载 unpacked extension，因此页面验证使用生产脚本与消息桥，结合实际 HTTP OCR、真实 DeepSeek 请求及保存结果重放。这不是 Windows Chrome/Edge 完整加载扩展后的站点验收。

本次修改带来的代价也需要明确：首次安装需要额外模型和依赖；长图有多次 OCR 请求；分组、掩膜和气泡判断仍有启发式成分；保留画面的策略可能留下原文和旁注；晚到的请求结果可以被丢弃，但并不意味着已经提交给后端的推理一定能立即中止。新增模型改善了适用范围，不等于消除了所有漏检和误擦。

当前仍未解决的内容应与已完成事项分开看待。

1. 紫底旁白仍有「思」被读成相似字等错误，部分专名和大喊句也有错字。尝试的二值化、背景去除、分列及不同边距没有稳定改善，没有为了样本强行替换文字。
2. 孤立「し」曾被译成不合语境的“而且”。这是片段上下文问题，不能用成功返回 API 来掩盖译意不准确。
3. 中文水印仍可能被 MangaOCR 当成日文，特别是分段识别时。普通对白与旁白是本轮目标，拟声词和艺术字未作为验收目标。
4. 页面内面板仍有新 Key 输入在宿主 DOM 中可读的风险；翻译来源之间也还共享部分 endpoint/Key 配置。需要后续将凭据输入放到扩展自身页面，并隔离各来源连接配置。
5. 复杂 object-position/cover、截图回退坐标空间、设置变化后重算已有结果、取图及响应体完整超时、部分异常响应格式处理仍需完善。
